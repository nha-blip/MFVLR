# MFVLR paper specification (implementation-neutral)

Source: *MFVLR: Multi-domain Fine-grained Vision-Language Reconstruction for Generalizable Diffusion Face Forgery Detection and Localization* (arXiv:2605.10071v1).

## Reading convention

- **PAPER-SPECIFIED** means the statement, tensor shape, equation, or value is explicitly stated or directly drawn in the paper.
- **NOT SPECIFIED / REQUIRES ASSUMPTION** means an implementation choice is necessary but is not defined by the paper. It must not be silently filled in from a standard CLIP, U-Net, or Transformer implementation.
- Shapes below omit the batch dimension unless the paper explicitly uses the batch index `u` or batch size `b`. The paper's symbols use `I` for an appearance image and `T` for its hierarchical fine-grained text prompt(s).

## 1. MFVLR: complete architecture and data flow

### PAPER-SPECIFIED: purpose and top-level modules

MFVLR is trained from scratch on facial images generated by multiple methods. Its task is generalizable diffusion-synthesized face forgery detection and localization (DFFDL). It has three top-level components:

1. **Multi-domain Vision Encoder (MVE)**: an Image Encoder (IE) and a Residual Encoder (RE) extract and fuse appearance/image and reconstruction-residual forgery features.
2. **Vision Decoder (VD)**: an Appearance Decoder (AD) reconstructs the appearance image; a Mask Decoder (MD) predicts a pixel-level manipulation mask.
3. **Fine-grained Language Transformer (FLT)**: a Language Encoder (LE) and a Language Decoder (LD), each incorporating Vision Injection Modules (VIMs), create global language features and reconstruct the input text prompt(s).

The final multi-domain visual feature is used in two heads:

- an **adapter** (a fully connected layer) produces a predicted language feature `T_lpre` for feature alignment with `T_l`;
- an **MLP head** (stated to contain a fully connected layer for detection) produces detection logits `y_pre`.

### PAPER-SPECIFIED: training data flow

For a training image-text pair `(I, T) ∈ D`, the paper gives one-hot detection label `y ∈ {[0, 1]^T, [1, 0]^T}` and ground-truth mask `M ∈ R^(224×224)` from GenFace. `T` is generated from GenFace hierarchical fine-grained labels; `M` is generated using the fake image and its corresponding source image.

The stated sequence is:

```text
appearance image I
  -> IE / MVE: local appearance feature I_loc and global appearance feature I_g
  -> VD(I_loc): reconstructed appearance I_pre and predicted mask M_pre
  -> residual generation(I, I_pre): residual image I_r = |I_pre - I|
  -> RE(I_r): global residual feature I_rg
  -> image-residual fusion: I_v = I_rg + I_g
  -> adapter(I_v): predicted language feature T_lpre
  -> MLP head(I_v): predicted detection logits y_pre

hierarchical text T + visual feature I_v
  -> FLT / LE with VIM: high-level text embeddings T_hig^e and global language feature T_l
  -> FLT / LD with VIM: reconstructed text embeddings T_rec^d
  -> vocabulary projection: reconstructed token labels T_pre
```

The supervised objective is the unweighted sum of the six losses in Section 9. Cross-modal contrastive learning aligns `I_v` with `T_l`; KL alignment aligns `T_lpre` and `T_l`.

### PAPER-SPECIFIED: inference data flow

At test time, the paper deliberately does **not** require texts, stating this prevents text information leakage and supports images from a new generator that may not have text prompts. It applies the trained **MVE, VD, and MLP head** only:

```text
I -> MVE produces I_loc
  -> VD produces I_pre and M_pre
  -> I_r = |I_pre - I|
  -> MVE image/residual processing produces I_v
  -> MLP head produces y_pre (real/fake detection)
```

`M_pre` is the localization output. The FLT, adapter, text reconstruction, CMC loss, KL loss, and their text inputs are training-only according to the stated inference description.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- The paper describes the MVE/VD/residual sequence conceptually but does not say whether appearance features/IE outputs are cached and reused or whether IE is run again after residual generation.
- It does not specify a detection decision rule: softmax/sigmoid at inference, a score threshold, or which logit corresponds to fake.
- It does not specify the form of the adapter beyond “a full connection layer,” nor the detailed MLP-head architecture beyond a fully connected layer.
- It does not state test-time mask post-processing, mask thresholding for output masks, resizing, connected-component filtering, or a detection/localization coupling rule.

## 3. Multi-domain Vision Encoder (MVE)

### PAPER-SPECIFIED

MVE contains an **Image Encoder (IE)** and **Residual Encoder (RE)**.

#### Image Encoder (IE)

IE contains a U-Net encoder and a Transformer Encoder (TE) with `B` image Transformer blocks `TB_j^i`, `j=1,2,...,B`.

1. Given `I ∈ R^(3×224×224)`, the U-Net encoder extracts `I_loc ∈ R^(c×h×w)`.
2. `I_loc` is sent to VD, producing `I_pre`.
3. Independently in the stated dataflow, `I_loc` is flattened, projected to `d` channels, appended with a learnable class token, then given a learnable position embedding. The paper writes:

```math
I_{tok} = \operatorname{App}(\operatorname{Proj}(\operatorname{Flat}(I_{loc}))) \in \mathbb{R}^{(hw+1)\times d},
```

```math
I^{tra}_1 = I_{tok} + P_i. \tag{1}
```

4. The exact TE composition stated by the paper is:

```math
\begin{aligned}
\operatorname{TE}(I^{tra}_1)
 &= \operatorname{TB}^{i}_{B} \circ \operatorname{TB}^{i}_{B-1} \circ \cdots \circ \operatorname{TB}^{i}_{2} \circ \operatorname{TB}^{i}_{1}(I^{tra}_1) \\
 &= \operatorname{TB}^{i}_{B} \circ \operatorname{TB}^{i}_{B-1} \circ \cdots \circ \operatorname{TB}^{i}_{2}(I^{tra}_2) \\
 &= \cdots = \operatorname{TB}^{i}_{B} \circ \operatorname{TB}^{i}_{B-1}(I^{tra}_{B-1}) \\
 &= \operatorname{TB}^{i}_{B}(I^{tra}_{B}) \\
 &= I_{TE}.
\end{aligned} \tag{2}
```

`I_g ∈ R^(1×d)` is the class token of `I_TE`.

#### Residual Encoder (RE) and fusion

RE has the **same architecture and weights** as IE, explicitly to reduce parameter count. It maps residual image `I_r` to `I_rg ∈ R^(1×d)`. MVE fuses the two global visual features by addition:

```math
I_v = I_{rg} + I_g.
```

`I_v` is then passed to the adapter and MLP head, and is the VIM vision input.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- The U-Net encoder architecture, its convolution/channel schedule, normalization, activation, and skip connections are not specified.
- The detailed image Transformer block structure, its number of heads, MLP width, normalizations, activations, dropout, stochastic depth, and class-token initialization are not specified.
- The source paper says RE shares the same architecture **and weights** with IE but does not specify the code-level sharing mechanism or whether any input-specific normalization exists.
- It does not specify alternatives to elementwise sum if feature distributions differ; fusion is explicitly addition only.

## 4. Vision Decoder (VD)

### PAPER-SPECIFIED

VD takes `I_loc` and contains two paths:

- **Appearance Decoder (AD):** a U-Net decoder plus an appearance-reconstruction module with a convolutional layer. It produces

  ```math
  I_{pre} = \operatorname{AD}(I_{loc}).
  ```

- **Mask Decoder (MD):** a U-Net decoder plus a manipulation-localization module with a convolutional layer. Its U-Net decoder uses the **same network and weights** as AD’s U-Net decoder. It produces

  ```math
  M_{pre} = \operatorname{MD}(I_{loc}) \in \mathbb{R}^{f\times224\times224},
  ```

  where `f` is the number of detection categories (`f=2` in the implementation details).

The paper’s stated reason for AD is to learn universal/general image forgery representations and extract residual information through appearance reconstruction. MD supplies pixel-level manipulation localization supervision.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- The U-Net decoder topology and the appearance/mask convolution details are not specified.
- The paper does not specify whether `M_pre` is logits, probabilities, or log-probabilities, though its localization loss applies `log(M_pre^u)`.
- It does not specify an activation for `I_pre` or `M_pre`, decoder skip connections, or how the single-channel `M` relates to `f=2` mask channels.

## 5. Residual generation

### PAPER-SPECIFIED

After appearance reconstruction, residual generation is pixelwise absolute difference:

```math
I_r = |I_{pre} - I|, \qquad I_r \in \mathbb{R}^{3\times224\times224}.
```

The residual is encoded by the weight-sharing RE, producing `I_rg`; fusing it with `I_g` yields `I_v`.

For forged face-swapped and attribute-edited training examples, the **ground-truth mask** is generated by taking the absolute pixelwise RGB difference between the fake and its corresponding source image, converting to grayscale, dividing by 255 to obtain `[0,1]`, then applying an empirically selected threshold of `0.1`. Real masks are set to 0, and entire-face-synthesis masks are set to 1.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- The residual is written as `|I_pre-I|`; the paper does not say whether it is retained in its original numeric range, normalized, clipped, or transformed before RE.
- It does not state RGB channel order, grayscale conversion formula, absolute-difference data type/range before division, or whether the mask threshold comparison is `>` or `>=`.
- It does not specify source-image pairing availability/handling outside GenFace or for any missing source counterpart.

## 6. Fine-grained Language Transformer (FLT)

### PAPER-SPECIFIED

FLT has a Language Encoder (LE) and Language Decoder (LD). Both include VIMs for vision-guided language representation learning. The paper introduces a fine-grained text generator (FTG) from MFCLIP to generate text prompts from L1 through L4 for each image using the GenFace hierarchical fine-grained labels.

### 6.1 Language Encoder (LE)

LE has `E` LE Transformer blocks `TB_j^e`, `j=1,2,...,E`.

1. Tokenize `T` to `T_tok^e ∈ R^n`.
2. Use vocabulary matrix `W_voc ∈ R^(s×d)` to form `T_low^e ∈ R^(n×d)`.
3. Add position embedding `P_e ∈ R^(n×d)`:

   ```math
   T^{tra}_1 = T^e_{low} + P_e.
   ```

4. Apply the `E` LE blocks. The paper’s exact composition is:

```math
\begin{aligned}
\operatorname{LE}(T^{tra}_1)
 &= \operatorname{TB}^{e}_{E} \circ \operatorname{TB}^{e}_{E-1} \circ \cdots \circ \operatorname{TB}^{e}_{2} \circ \operatorname{TB}^{e}_{1}(T^{tra}_1) \\
 &= \operatorname{TB}^{e}_{E} \circ \operatorname{TB}^{e}_{E-1} \circ \cdots \circ \operatorname{TB}^{e}_{2}(T^{tra}_2) \\
 &= \cdots = \operatorname{TB}^{e}_{E} \circ \operatorname{TB}^{e}_{E-1}(T^{tra}_{E-1}) \\
 &= \operatorname{TB}^{e}_{E}(T^{tra}_{E}) \\
 &= T^e_{hig}.
\end{aligned} \tag{3}
```

LE takes its global language feature from the final token:

```math
T_l \in \mathbb{R}^{1\times d} = \text{the last token of } T^e_{hig}.
```

Within LE block `TB_j^e`, the paper first runs LN and MHA with residual addition:

```math
T^j_{tok} = \operatorname{MHA}^{e}_{j}(\operatorname{LN}^{e}_{j}(T^{tra}_{j})) + T^{tra}_{j} \in \mathbb{R}^{n\times d}.
```

It next applies VIM to the word representations and `I_v`, then an FF layer with residual addition:

```math
T^j_{add} = T^j_{glo}W^j_{fc} + T^j_{tok}, \qquad W^j_{fc}\in\mathbb{R}^{d\times d},
```

```math
T^{tra}_{j+1} = \operatorname{FF}^{e}_{j}(T^j_{add}) + T^j_{add} \in \mathbb{R}^{n\times d}.
```

### 6.2 Language Decoder (LD)

LD has `D` LD Transformer blocks `TB_j^d`, `j=1,2,...,D`, and reconstructs the original text prompt(s), guided by `T_low^e`, `T_hig^e`, and `I_v`.

1. Append a begin token to `T_low^e` and remove the final token so the sequence length stays `n`; add `P_d ∈ R^(n×d)` to obtain `T_t1^tra ∈ R^(n×d)`. The stated purpose is next-word prediction.
2. The decoder composition is:

```math
\begin{aligned}
\operatorname{LD}(T^{tra}_{t1}, T^e_{hig}, I_v)
 &= \operatorname{TB}^{d}_{D} \circ \cdots \circ \operatorname{TB}^{d}_{2} \circ \operatorname{TB}^{d}_{1}(T^{tra}_{t1}, T^e_{hig}, I_v) \\
 &= \operatorname{TB}^{d}_{D} \circ \cdots \circ \operatorname{TB}^{d}_{2}(T^{tra}_{t2}, T^e_{hig}, I_v) \\
 &= \cdots = \operatorname{TB}^{d}_{D}(T^{tra}_{tD}, T^e_{hig}, I_v) \\
 &= T^d_{rec}.
\end{aligned} \tag{12}
```

3. For LD block `TB_j^d`, the paper specifies the following exact ordering:

```math
T^{mmha}_{tj} = \operatorname{MMHA}^{d}_{j}(T^{tra}_{tj}) + T^{tra}_{tj}. \tag{13}
```

The MMHA is masked so each word integrates only itself and earlier words, preventing information leakage.

```math
T^{mha}_{tj} = \operatorname{MHA}^{d}_{j}(T^{mmha}_{tj},T^e_{hig}) + T^{mmha}_{tj}. \tag{14}
```

```math
T^{ff}_{tj} = \operatorname{FF}^{d}_{j}(T^{mha}_{tj}) + T^{mha}_{tj}. \tag{15}
```

```math
T^{tra}_{t(j+1)} = \operatorname{VIM}^{d}_{j}(T^{ff}_{tj}, I_v) + T^{ff}_{tj}. \tag{16}
```

Thus, VIM is between MHA and FF in LE, and after MHA and FF in LD. The ablation specifies the best of the tested VIM placements as this LE/LD arrangement.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- The paper does not state the exact FTG implementation, tokenizer variant/configuration, vocabulary file, begin-token ID, padding token, padding mask, or text truncation policy.
- It does not explicitly state whether L1--L4 are concatenated into one token sequence, processed as separate prompts, or otherwise packed to reach `n=308`; Fig. 4 depicts four prompt lines as `T`, while the equations use a single sequence.
- The LE/LD Transformer hidden width is inferable as `d=512`, but head count, FF expansion ratio, activation, layer-norm placement beyond the displayed LE LN, dropout, causal-mask construction, and decoder MHA query/key/value assignments are not stated.
- The paper says `T_low^e` is shifted with a begin token and its last token removed, but does not state the precise target-token alignment convention for `T_gt`.

## 7. Vision Injection Module (VIM): exact Q/K/V design

### PAPER-SPECIFIED

VIM is a plug-and-play module for word-level visual-language interaction. Its key efficiency decision is to use **only the visual class token** `I_v`, rather than all visual/image patch tokens, as key and value. The paper says this makes attention-map cost linear instead of quadratic.

For VIM in the `j`-th language block, language word features `T_tok^j` are the query source. Visual feature `I_v` is the key and value source. The learnable matrices `W_que^j`, `W_key^j`, and `W_val^j` all have shape `R^(d×d)`.

```math
q_j = T^j_{tok}W^j_{que}, \tag{4}
```

```math
k_j = I_vW^j_{key}, \tag{5}
```

```math
v_j = I_vW^j_{val}. \tag{6}
```

Partition query, key, and value into `r` heads:

```math
\{Q_{j,i}\in\mathbb{R}^{n\times \frac{d}{r}}\}_{i=1}^{r}=\operatorname{Pa}(q_j), \tag{7}
```

```math
\{K_{j,i}\in\mathbb{R}^{1\times \frac{d}{r}}\}_{i=1}^{r}=\operatorname{Pa}(k_j), \tag{8}
```

```math
\{V_{j,i}\in\mathbb{R}^{1\times \frac{d}{r}}\}_{i=1}^{r}=\operatorname{Pa}(v_j). \tag{9}
```

Perform cross-attention independently in every head:

```math
T^{glo}_{j,i}=\delta\left(\frac{Q_{j,i}K^T_{j,i}}{\sqrt{d/r}}\right)V_{j,i}, \tag{10}
```

where `δ` is softmax. Concatenate the head outputs:

```math
T^j_{glo}=\operatorname{Cat}(\{T^{glo}_{j,i}\}_{i=1}^{r})\in\mathbb{R}^{n\times d}. \tag{11}
```

The paper then applies its fully connected output projection and adds the original language feature:

```math
T^j_{add}=T^j_{glo}W^j_{fc}+T^j_{tok}, \qquad W^j_{fc}\in\mathbb{R}^{d\times d}.
```

It is this `T_add^j` that flows to LE’s FF residual update. LD is stated to contain `VIM_j^d` and invokes it as in Equation (16).

### NOT SPECIFIED / REQUIRES ASSUMPTION

- The number of VIM heads `r` is not reported.
- The paper gives Equations (4)--(11) using LE notation `T_tok^j`; it does not separately restate LD’s Q/K/V projection symbols or say whether LE and LD VIM projections are tied. The only safe statement is that LD uses its own named `VIM_j^d` in Equation (16).
- No attention bias, projection bias, dropout, precision, initialization, or softmax masking is specified for VIM.
- Because each head has one key/value position, the equations mathematically yield a single-item attention distribution per word; the paper does not discuss this consequence or specify any additional visual tokens.

## 8. Hierarchical prompts L1--L4

### PAPER-SPECIFIED

The fine-grained text generator uses GenFace hierarchical labels to generate text prompts from L1 to L4 for each image. Figure 6 gives the following template hierarchy:

| Level | Prompt content | Exact examples shown |
|---|---|---|
| L1 | authenticity | `A photo of a real face`; `A photo of a fake face` |
| L2 | real/fake type | `A photo of a real face`; `A photo of an entire synthesized face`; `A photo of an identity swapped face`; `A photo of an attribute manipulated face` |
| L3 | source family | `A photo of a real face`; `A photo generated by the diffusion-based model`; `A photo generated by the GAN-based model` |
| L4 | named source generator | `A photo of a real face`; `The source generative model of this photo is [generator]` |

Figure 6’s visible named L4 examples include `DDPM`, `LatDiff`, `CollDiff`, `StyleGAN3`, `DiffFace`, `FSLSD`, `FaceSwapper`, `Diffae`, `LatentTransformer`, and `IA-FaceS` (as displayed in the figure). The methodological text also describes GenFace categories as entire face synthesis (EFS), attribute manipulation (AM), and face swapping (FS), and gives dataset examples: EFS: DDPM, LatDiff, CollDiff; AM: Diffae, LatTrans, IAFaces; FS: FSLSD, FaceSwapper.

The prompt ablation adds L1 through L4 progressively and reports stronger results with more levels. It also reports sensitivity to omitting L2 and L4. For cross-dataset experiments trained on FF++, only L1 and L2 are used because FF++ has limited class labels.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- Beyond the shown templates/examples, the full mapping of every generator to exactly one L2/L3/L4 string is not formally enumerated in the method.
- The paper does not define punctuation, separators, tokenization of the four sentences, prompt ordering beyond the illustrated L1-to-L4 order, or how to handle unknown generators/classes.
- It does not specify the train/test sampling distribution over prompt variants or whether prompt text is augmented.

## 9. Exact loss functions

### PAPER-SPECIFIED

All six losses are summed with coefficient 1; no per-loss weighting is shown:

```math
\mathcal{L}=\mathcal{L}_{fd}+\mathcal{L}_{lr}+\mathcal{L}_{cmc}+\mathcal{L}_{fl}+\mathcal{L}_{ar}+\mathcal{L}_{kl}. \tag{27}
```

### Appearance reconstruction loss `L_ar`

```math
\mathcal{L}_{ar}=\frac{1}{b}\sum_{u=1}^{b}(I^u-I^u_{pre})^2. \tag{17}
```

The paper describes it as reducing discrepancy between `I_pre` and `I`.

### Forgery localization loss `L_fl`

```math
\mathcal{L}_{fl}=\frac{1}{b}\sum_{u=1}^{b}-(M^u)^T\log(M^u_{pre}). \tag{18}
```

### KL-divergence feature-alignment loss `L_kl`

`I_v` goes through the adapter to produce `T_lpre ∈ R^(1×d)`. The paper applies softmax `δ` with temperature `0.5` to smooth features:

```math
\mathcal{L}_{kl}=\frac{1}{b}\sum_{u=1}^{b}\delta(T^u_l)^T\log\frac{\delta(T^u_l)}{\delta(T^u_{lpre})}. \tag{19}
```

### Cross-modal contrastive loss `L_cmc`

For the vision-language pairs `\{(I_v^u,T_l^u)\}_{u=1}^{b}`, the paper defines:

```math
S^u_{v2l}(I_v,T_l)=
\frac{\exp(\operatorname{sim}(I_v^u,T_l^m)/\tau)}
{\sum_{m=1}^{b}\exp(\operatorname{sim}(I_v^u,T_l^m)/\tau)}, \tag{20}
```

```math
S^u_{l2v}(T_l,I_v)=
\frac{\exp(\operatorname{sim}(T_l^u,I_v^m)/\tau)}
{\sum_{m=1}^{b}\exp(\operatorname{sim}(T_l^u,I_v^m)/\tau)}. \tag{21}
```

`sim(·)` is explicitly described as a dot product for similarity. `τ` is a trainable temperature initialized to `0.07`. `u,m=1,2,...,b` index samples. The pair target is `y^u_{pa}=\{y^{u,m}_{pa}\}_{m=1}^{b}`, with `y^{u,u}_{pa}=1` and `y^{u,m}_{pa}=0` when `u\ne m`.

```math
\mathcal{L}_{v2l}=\frac{1}{b}\sum_{u=1}^{b}-(y^u_{pa})^T\log(S^u_{v2l}(I_v,T_l)), \tag{22}
```

```math
\mathcal{L}_{l2v}=\frac{1}{b}\sum_{u=1}^{b}-(y^u_{pa})^T\log(S^u_{l2v}(T_l,I_v)), \tag{23}
```

```math
\mathcal{L}_{cmc}=(\mathcal{L}_{v2l}+\mathcal{L}_{l2v})/2.
```

### Language reconstruction loss `L_lr`

Project decoder text embeddings using the vocabulary matrix:

```math
T_{pre}=T^d_{rec}W^T_{voc}\in\mathbb{R}^{n\times s}. \tag{24}
```

Then use the stated tokenwise reconstruction loss:

```math
\mathcal{L}_{lr}=\frac{1}{b}\sum_{u=1}^{b}\sum_{x=1}^{n}-(T^{u,x}_{gt})^T\log(T^{u,x}_{pre}). \tag{25}
```

Here `x` is word index and `T_gt ∈ R^(n×s)` is the text ground-truth one-hot label.

### Forgery detection loss `L_fd`

```math
\mathcal{L}_{fd}=\frac{1}{b}\sum_{u=1}^{b}-(y^u)^T\log(y^u_{pre}). \tag{26}
```

`y_pre` is obtained by feeding `I_v` to the MLP head.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- Equations (17), (18), (25), and (26) use `log` of output quantities but do not state where softmax, sigmoid, or log-softmax is applied. An implementation must choose a numerically stable formulation without claiming it was specified.
- Equation (17) does not state whether the square/error is summed or averaged over image channels and pixels; it only explicitly averages over batch samples.
- Equation (18) does not state how a one-channel ground-truth `M` is aligned with a stated two-category prediction `M_pre ∈ R^(2×224×224)`, whether it is BCE or multiclass CE in code, or the reduction over pixels/classes.
- Equation (20) and Equation (21) use the free denominator index `m` in the numerator as printed in the paper. Their intended standard interpretation is the vector of all batch-pair similarities, but the exact indexing/normalization expression is not fully disambiguated typographically by the paper.
- The paper calls `sim` a dot product while introducing the calculation as “cosine similarity”; it does not specify explicit L2 normalization. Do not assume it.
- No loss weighting, label smoothing, ignore-index, masking of padding tokens, or class imbalance treatment is stated.

## 10. Training pipeline

### PAPER-SPECIFIED

1. Train MFVLR from scratch on GenFace facial images. The paper says the dataset contains EFS, AM, and FS examples from advanced generators.
2. Form image-text pairs `(I,T)`, labels `y`, and masks `M` as described above. Generate hierarchical prompts from GenFace labels.
3. Encode `I` with IE, reconstruct `I_pre` and predict `M_pre` from `I_loc`, form `I_r=|I_pre-I|`, encode the residual with weight-sharing RE, and sum global features to form `I_v`.
4. Encode text with LE while injecting `I_v` using VIM; extract `T_l` from the final LE token.
5. Decode/reconstruct text using the shifted low-level text embedding, `T_hig^e`, `I_v`, masked attention, MHA, FF, and VIM; project `T_rec^d` into `T_pre`.
6. Produce `T_lpre` through the adapter and `y_pre` through the MLP head.
7. Optimize the total loss in Equation (27).

The stated runtime framework/hardware is PyTorch on a Tesla V100 GPU. The optimizer is Adam with learning rate `1e-4` and weight decay `1e-3`. The scheduler reduces the learning rate by a factor of ten every 15 epochs.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- The number of training epochs, Adam betas/epsilon, schedule implementation, scheduler start point, optimizer parameter groups, gradient clipping, mixed precision, accumulation, seed, checkpoint selection, and validation protocol are not stated.
- Dataset split sizes, sampling ratios between real/fake/classes/generators, input normalization, face crop/alignment, resizing procedure, augmentation, and loader-worker setup are not stated.
- The paper does not state initialization/pretraining of any component; it says MFVLR is trained from scratch, but provides no initialization recipe.

## 11. Inference pipeline

### PAPER-SPECIFIED

1. Start with appearance image `I`; no text prompt is used.
2. Obtain `I_loc`, send it to VD, and output `I_pre` and `M_pre`.
3. Generate `I_r=|I_pre-I|`; use MVE’s image/residual processing to obtain `I_v`.
4. Use the MLP head to generate `y_pre`, giving real/fake detection, alongside `M_pre` for localization.

The paper’s reason for excluding text at test time is prevention of text information leakage and practical availability for images from unseen generators.

### NOT SPECIFIED / REQUIRES ASSUMPTION

- No numerical decision threshold, probability conversion, batch inference layout, test-time augmentation, mask export format, or timing/FLOPs evaluation protocol is supplied.
- The paper does not define behavior for a non-face image, multiple faces, corrupted image, or non-224×224 input.
